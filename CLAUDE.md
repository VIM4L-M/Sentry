# SENTRY AI

## General Rules

Never rewrite existing working code.

Keep modules loosely coupled.

Never create cyclic imports.

Use Python typing everywhere.

Document every public class.

Every phase must compile before moving to next phase.

Every feature must have unit tests.

Every AI model should be isolated.

Every module should expose clear interfaces.

Keep functions under 40 lines whenever possible.

Prefer composition over inheritance.

Never duplicate logic.

Use dataclasses.

Use logging.

Avoid hardcoded paths.

All constants belong in config files.

Every commit should represent one milestone.

Follow Clean Architecture.

Follow SOLID.

Use dependency injection.

No placeholder code.

No TODO comments unless explicitly requested.

Never skip documentation.

Always update README whenever architecture changes.

Think before implementing.
